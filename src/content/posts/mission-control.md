一个项目最容易失控的地方，往往不是代码本身，而是流程。什么时候安装依赖，什么时候检查类型，什么时候构建，什么时候部署，如果这些动作只能靠记忆，就很容易在某个深夜失联。

我更喜欢把流程写成明确的脚本。比如 `dev` 用来启动本地环境，`build` 用来做完整检查和生产构建，`preview` 用来确认构建结果。每个命令都像任务控制台上的一个按钮，职责清楚，状态可见。

## 本地和线上保持一致

GitHub Actions 里的步骤应该尽量复用本地命令，而不是重新写一套逻辑。这样当本地 `npm run build` 通过时，线上也更可能通过；当线上失败时，也能回到本地快速复现。

## 自动化不是炫技

自动化的目标不是堆满工具，而是减少重复判断。对于个人博客，最小闭环就是：写文章、构建检查、自动发布。等这个闭环稳定后，再考虑评论、搜索、统计或者更多互动能力。

好的流程像一条清晰航线：它不会替你写代码，但会让每一次起飞都更可控。
